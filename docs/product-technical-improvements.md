# Patty 产品与技术改善清单

日期：2026-11-02。依据当前代码、Ghostty 与 Otty 官方资料整理。按用户授权逐项实现、验证和提交；清单中的待办不等于已交付功能。

## 目标与边界

让 Windows 用户更快找到本地、SSH 和 AI 会话，集中处理需要输入的任务，并在关闭后继续原有 AI 对话。保留 Tauri、React、xterm.js 与现有分屏和集合模型。

用户已选择 CLI 原生 Resume 路线。恢复对话会启动新的 CLI 进程，不承诺恢复运行中的命令或让进程跨应用退出保活。常驻 PTY 服务、自动重跑任意命令、替换终端内核不在当前实施范围。

## 优先级与依赖

P0 解决查找和注意力管理。P1 使会话可继续，并补齐命令语义。P2 提高重复工作效率。P3 由实际测量决定性能优化和内核方向。同级按表中顺序推进，依赖未满足的条目保持待办。

## 首批实施计划（4+1）

### 目标

完成 P0-01、P0-02，减少多会话查找和查看提醒的切换次数。查询与注意力筛选共用纯函数，列表 UI 不各自维护不同的匹配规则。

### 非目标

不修改 Hook 协议与持久化，不新增运行中状态，不自动执行命令，不恢复进程，不改变集合/工作区归属。

### 影响模块

`src/renderer/components/Sidebar/` 的查询、列表、工具栏与样式，新增行为测试和可重跑桌面 E2E，更新 README 使用说明。现有 TerminalPane 与 workspace 负责终端实例和布局，不迁移它们的所有权。

### 回滚

每张票一个功能提交，包含测试和文档。使用对应 commit 的 revert 撤回；首批不改落盘数据，因此不存在新旧格式转换。提交到当前本地分支，不推送、不发布、不修改用户的实际会话或 CLI 配置。

### 提交顺序

1. `docs: add product and technical improvement backlog`：提交清单及已有产品约束。
2. `test: isolate desktop verification profiles`：P0-00，隔离测试账户与启动诊断；这是执行时发现并经用户确认的前置工作。
3. `feat: search sessions by project and connection context`：P0-01，纯查询与侧栏行为验证。
4. `feat: filter sessions that need attention`：P0-02，数量、组合查询、空状态与键盘操作。
5. 后续条目在开始前补充对应目标、非目标、模块、回滚与验收，不把多个票混进同一功能提交。

## 验证方式

变更前基线为 70 个测试文件、671 个前端测试通过。每项先运行针对性测试，再执行 `npm test`、`npm run typecheck`、`npm run check:comments`。UI 通过真实桌面 harness 验证搜索、筛选和焦点；原生改动必须先证明后端测试失败，再实现并运行 Cargo 测试。

不得因为编译通过而标记完成。只有验收行为通过并记录提交后才更新表格状态。测试连续三次真实修复仍失败时记录原因并按 AGENTS.md 升级处理。

## P0-03 实施计划与结果

本项 4+1 计划及统一状态对象路线已经用户确认。

1. 目标：分别表示空闲、工作中、等待批准、等待回答、完成和错误；已读仅停止提醒效果，新一轮工作替换过期完成或错误。
2. 非目标：不实现 Resume、持久化迁移、OSC 或系统通知。不会根据任意键盘输入推断 CLI 已经开始工作。
3. 影响模块：Rust Hook 归一、共享 Agent 类型及 IPC 边界、会话 store、终端与命令输入、侧栏状态和筛选、OpenCode/omp 适配器及回归测试。
4. 回滚：撤回本项功能 commit，无需转换落盘数据。
5. 提交：`feat: separate agent activity from unread attention`，包含实现、测试与文档。

内部事件统一为 `pty:agent` 的 `{paneId, agent: {aiType, status} | null}` 对象。旧元组、旧提醒 setter 和单独设置身份的 API 已在同一提交迁移。Hook HTTP 请求格式保持兼容，事件词汇记录升为 v3。已读信息只在前端保存，工作中和空闲状态不能携带 unread=true。

批准请求显示 Waiting for approval，问题和输入提示显示 Waiting for answer。会话选择和终端输入标记已读，保留运行状态及需要处理分类。收到 Prompt 提交、工具执行或 OpenCode 主会话 busy 后显示 Working。Oh My Pi 工具调用改为报告工作事件，定时 alive 仍只续期心跳。重复状态不会重新点亮已经阅读的提醒；下一轮工作结束后可以再次产生未读完成提醒。

启动期间暂存各 pane 最新状态，待会话恢复完成再应用。关闭会话、PTY 退出和 Agent 清除同时移除身份与状态。恢复布局不恢复旧的运行状态。已有子 Agent 隔离测试继续通过。

先验证 Rust 工作状态测试失败，再实现映射；OpenCode/omp 适配器契约也先观察新断言失败再修正。最终前端 73 个测试文件、700 项测试通过；普通和 E2E 两种 Cargo 配置各 262 项测试通过。类型检查、注释检查、桌面脚本语法检查通过。真实 React/store 验证已读后的状态、文案、光效和筛选，以及 Working 替换旧状态；测试仅替换 jsdom 无法绘制的装饰 Canvas，不替换 store 或筛选逻辑。桌面隔离脚本确认六种适配器安装与退出清理继续正常。

普通发布构建和 E2E 构建均成功。普通发布程序拒绝测试变量、启动前不创建 WebView2 数据或安装 Hook 的检查再次通过。

本项没有重新宣称 CDP 桌面验收通过，也没有证明各 CLI 现场运行的全部事件。适配器仍依赖 CLI 提供的事件，完整的迟到事件与生命周期测试保留在 P0-05。

## P0-04 实施计划与结果

本项 4+1 计划已经用户确认。

1. 目标：增加 Next attention 按钮，按现有会话顺序循环等待批准、等待回答和错误的会话；搜索、当前视图和集合折叠不限制目标，零命中时禁用。
2. 非目标：不新增全局快捷键、通知、存储字段或终端进程。
3. 影响模块：侧栏控件、注意力查询、工作区定位、回归测试和桌面脚本。
4. 回滚：撤回本项功能 commit，无数据迁移。
5. 提交：`feat: navigate to the next session needing attention`，包含循环导航、跨工作区分屏定位和已读语义验证。

先用回归测试复现 `ensureVisible` 的跨工作区焦点缺陷：目标会话存在于另一个分屏工作区时，切换后仍保留同级 pane 的旧焦点。修正后工作区 ID 和目标 focusedPaneId 在一次状态更新中完成；当前工作区的会话优先匹配，保留原有找不到工作区时的创建行为。

按钮在点击时读取最新会话状态，按会话数组顺序从当前会话之后查找，末尾回绕。没有活动会话时从首个命中开始；只有当前会话待处理时保留该目标。已读不改变资格，完成、工作中、空闲和已关闭会话不参与导航。选择复用现有 selectSession，因此标记已读但保留运行状态；搜索条件、视图和集合折叠状态保持不变。

新增 4 项查询行为、2 项真实 Sidebar/store 集成行为和 1 项跨工作区回归，共 74 个前端测试文件、707 项测试通过。类型检查、注释检查及桌面脚本语法检查通过。控件使用原生 button，具备禁用状态、可访问名称和键盘焦点样式。集成测试直接验证目标工作区、focusedPaneId、会话身份和 unread，不替换会话或工作区逻辑；仅替换 jsdom 无法绘制的装饰 Canvas。

普通发布构建通过。回归测试还通过实际 store 订阅验证工作区切换只暴露目标会话，不产生旧同级 pane 的中间焦点。普通构建拒绝测试覆盖变量及清理临时目录的检查再次通过。本项没有修改 Rust 后端。

桌面工作流脚本已补充在无搜索结果及 Completed 视图下跳转、循环和已读状态的断言。当前 CDP 阻塞保持不变，这些脚本断言尚未在本机通过 CDP 执行，不计为桌面验收通过。

## P0-05 实施计划与结果

用户已确认扩展事件归属后完整修正，分两个可验证提交推进。

1. 目标：识别事件所属运行实例及顺序，防止关闭、过期、重复和迟到事件影响新运行或其他会话。
2. 非目标：不实现 Resume、会话历史、持久化迁移或常驻 PTY。
3. 影响模块：Hook 协议、PowerShell/Node 适配器、Rust 运行身份与租约状态、IPC 和前端状态校验。
4. 回滚：按提交撤回协议及实现。适配器更新后重启 CLI；不转换落盘数据。
5. 提交顺序：先 `feat: identify hook producers and sequence events`；再交付生命周期处理与回归。

现有 `heartbeat_lease_reopens_on_late_event` 测试明确要求退出后的迟到事件重新开租约，已执行并确认该旧行为。当前请求只有 pane/source，无法区分同一 pane 的前后两次运行。Claude、Codex 的原生对话 ID 可跨 Resume 使用，不能代替运行实例身份。

基础提交增加 `origin`，携带调用进程、事件序号及可用的对话身份。Node 适配器另带每次加载生成的随机实例标识；PowerShell 即使收到强制 EventType 也读取原生对话身份，并转发明确的子 Agent 标记。Windows 身份解析只读取进程名称、父进程和内核创建时间，沿父链验证其属于对应终端，不读取命令行或环境变量。纯父链测试与实际 Node 子进程测试共 5 项通过；该提交普通 Rust 全量为 267 项通过。基础提交本身尚未连接生命周期处理，因此当时未标记 P0-05 完成。

第二个提交连接运行实例校验和租约状态。只有当前本地 PTY 内有效主实例的显式开始事件可建立租约。旧实例、旧会话、重复或倒序状态不能覆盖新状态；结束后的 idle 和 alive 不能重开租约。心跳不推进状态序号，避免丢弃仍有效的延迟审批事件。子 Agent 只能续期匹配主会话的现有租约，不能打开、关闭或替换主状态。

进程退出由 Windows 进程身份检查确认，最长等待一个五秒检查周期。OpenCode 和 omp 的心跳超过八秒且进程仍存活时显示 Status unavailable，保留工具身份，等待新鲜状态事件恢复。Claude、Codex、Qwen、Copilot 没有周期心跳，静默不作为退出依据。PTY 关闭、预热终端替换和通知停用都会清除对应状态。关闭布局 pane 保留后台会话及其状态；OSC 7 只更新目录，不再推断 Agent 退出。

IPC 更新增加单调递增的 revision。窗口先完成订阅再读取快照，合并快照水位之后的事件，丢弃旧清除及旧状态。重叠加载会取消旧监听器，取消后的异步结果不能覆盖新会话。移除了旧的无版本清理命令和全部调用方。这里恢复的是仍在后端运行的状态，没有增加跨应用重启的持久化能力。

真实 HTTP/curl 测试先复现退出通知缺少 stdin 的问题，再修正两个 Node 适配器。OpenCode 另有两项先失败的回归：删除旧主会话或缺失 parentID 的已知子会话会停止当前主会话心跳。修正后心跳只随当前主会话结束而停止。真实 ConPTY 回归也先复现预热进程替换遗漏状态清理，再补齐对应根实例的退役处理。

`npm test` 为 75 个文件、721 项通过；`cargo test` 与 `cargo test --features e2e` 各 253 项通过。新增生命周期、事件归属、协议入口、快照顺序、取消监听和真实退出通知的行为断言。旧的 ACTIVE/compute_hook_events 测试随旧接口删除，由新 registry 的行为测试替代。类型检查、注释检查与两份桌面脚本语法检查通过。CDP 工作流脚本已迁移到带版本的事件，但本机 CDP 阻塞未解除，未计为已执行验收。

`npm run build:e2e` 和普通 `npx tauri build --no-bundle` 均成功。E2E 程序通过六种 CLI 适配器安装与临时目录清理检查；普通发布程序通过测试覆盖变量拒绝检查，在启动 WebView2 和安装 Hook 前退出。未改动真实 CLI 配置。更新 Hook 协议和 Node 插件后需要重启已运行的 CLI。
