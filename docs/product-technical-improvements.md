# Patty 产品与技术改善清单

日期：2026-11-02。依据当前代码、Ghostty 与 Otty 官方资料整理。按用户授权逐项实现、验证和提交；清单中的待办不等于已交付功能。

## 目标与边界

让 Windows 用户更快找到本地、SSH 和 AI 会话，集中处理需要输入的任务，并在关闭后继续原有 AI 对话。保留 Tauri、React、xterm.js 与现有分屏和集合模型。

用户已选择 CLI 原生 Resume 路线。恢复对话会启动新的 CLI 进程，不承诺恢复运行中的命令或让进程跨应用退出保活。常驻 PTY 服务、自动重跑任意命令、替换终端内核不在当前实施范围。

## 优先级与依赖

P0 解决查找和注意力管理。P1 使会话可继续，并补齐命令语义。P2 提高重复工作效率。P3 由实际测量决定性能优化和内核方向。同级按表中顺序推进，依赖未满足的条目保持待办。

## 首批实施计划（4+1）

### 目标

完成 P0-01、P0-02，减少多会话查找和查看提醒的切换次数。查询与注意力筛选共用纯函数，列表 UI 不各自维护不同的匹配规则。

### 非目标

不修改 Hook 协议与持久化，不新增运行中状态，不自动执行命令，不恢复进程，不改变集合/工作区归属。

### 影响模块

`src/renderer/components/Sidebar/` 的查询、列表、工具栏与样式，新增行为测试和可重跑桌面 E2E，更新 README 使用说明。现有 TerminalPane 与 workspace 负责终端实例和布局，不迁移它们的所有权。

### 回滚

每张票一个功能提交，包含测试和文档。使用对应 commit 的 revert 撤回；首批不改落盘数据，因此不存在新旧格式转换。提交到当前本地分支，不推送、不发布、不修改用户的实际会话或 CLI 配置。

### 提交顺序

1. `docs: add product and technical improvement backlog`：提交清单及已有产品约束。
2. `test: isolate desktop verification profiles`：P0-00，隔离测试账户与启动诊断；这是执行时发现并经用户确认的前置工作。
3. `feat: search sessions by project and connection context`：P0-01，纯查询与侧栏行为验证。
4. `feat: filter sessions that need attention`：P0-02，数量、组合查询、空状态与键盘操作。
5. 后续条目在开始前补充对应目标、非目标、模块、回滚与验收，不把多个票混进同一功能提交。

## 验证方式

变更前基线为 70 个测试文件、671 个前端测试通过。每项先运行针对性测试，再执行 `npm test`、`npm run typecheck`、`npm run check:comments`。UI 通过真实桌面 harness 验证搜索、筛选和焦点；原生改动必须先证明后端测试失败，再实现并运行 Cargo 测试。

不得因为编译通过而标记完成。只有验收行为通过并记录提交后才更新表格状态。测试连续三次真实修复仍失败时记录原因并按 AGENTS.md 升级处理。

## 验收环境记录

2026-11-02，本机 WebView2 156 的 CDP 端口持续拒绝连接，应用与 shell 本身正常运行。已尝试独立数据目录、显式 DevTools 构建和 API 传参，并获取浏览器进程参数与日志。运行时提示调试需要非默认数据目录，但显式浏览器目录参数未生效。三次失败后按 AGENTS.md 升级，用户批准改用组件行为测试与原生窗口验收。没有修改系统策略、浏览器安全设置或下载旧运行时；未奏效的构建特性已撤回。

搜索的原生窗口验收确认了多字段命中、折叠集合内会话显示、正斜杠路径查询，以及结果切换到正确终端。CDP 自动化仍是环境阻塞，不标记通过。参考 [微软官方问题记录](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5718)。
