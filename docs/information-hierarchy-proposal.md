# Patty 信息层级与界面降噪方案

日期：2026-11-03。状态：调研和设计记录。用户修订后的核心界面已实施，实际行为与验证见[交付记录](quiet-workbench.md)。下文保留原调研与方案，不将初版建议视为当前产品行为。

## 用户修订后的设计方向

2026-11-03，用户进一步明确界面应由“终端内容”和“其余应用区域”两部分构成。此节为最新设计要求，下文初版中关于保留终端标题条、常驻搜索输入框和待处理文字栏的建议已被替代，实施计划须按此修订后再确认。

| 元素 | 最新方向 |
|---|---|
| 左上角 | 去掉应用名称、命令入口文字及 Sessions 数量标题等冗余展示，只留必要的小型操作按钮 |
| 查找 | 取消常驻搜索输入框，使用搜索图标按钮；会话查找与应用命令查找使用同一个临时界面 |
| 待处理 | 取消 Needs you 文字栏，改为铃铛通知按钮；有待处理信息时显示低强度标记，主动打开后展示具体状态与跳转目标 |
| 终端顶栏 | 移除每个终端的标题、工具图标、目录、操作按钮条；切换焦点时以对应侧栏会话的选中颜色表示当前目标 |
| 分屏 | 内容直接开始，仅保留必要的细分隔线；不再用独立卡片、醒目描边和重复标题强调每个 pane |
| 应用顶栏和侧栏 | 背景、色调和材质一致，交界处不再设置强分隔，形成一体的应用区域 |
| 详情与操作 | 通过通知、统一查找、上下文菜单等临时入口呈现，不以新增常驻栏补回已经移除的信息 |
| 远程识别 | 简短的远程目标保留在对应侧栏会话行，不为此重新添加终端顶栏 |

最新效果图展示默认关闭通知和查找时的工作界面。它属于视觉提案，图标点击、通知分组、键盘操作、分屏焦点对应关系和侧栏收起后的定位方式仍须在实施前具体定义与验证。

本方案依据当前代码、现有浏览器验收截图和网上的一手资料。截图来自使用模拟终端传输的组件验收页面，并非本轮重新进行的原生桌面实测。本轮不修改产品代码，不恢复此前暂停的 AI 会话恢复等功能开发。

## 建议方向

让终端内容占据主要注意力。侧栏负责找到会话和识别需要处理的会话；分屏标题负责确认当前输入目标；细节按需查看。先减少重复信息和常驻提示，再统一视觉重量。

目前的主要问题是多个区域同时解释同一个会话，正常状态和异常状态的提示差异也不够明确。继续增加标签、动画和说明会放大这个问题。第一轮应优先删除冗余展示，同时保留用户判断操作对象所需的信息。

这里的“高级感”作为设计目标，具体落实为稳定的布局、明确的主次、克制的颜色、可预测的操作和清晰可读的文字。审美评价与任务效率需要分别验证。

## 网上经验及适用边界

### 信息越多，用户越需要明确的层级

NN/g 的美学与极简设计准则指出，额外信息会与相关信息竞争可见性。它同时强调，界面需要包含支持任务的必要信息。对 Patty 的启示是先去重、再分级，避免通过删除关键上下文来获得表面简洁。[NN/g：Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)

一项包含 165 名参与者的网页实验发现，较高的视觉复杂度会损害信息搜索效率和回忆表现，个人偏好也会影响结果。该研究支持关注视觉复杂度，但实验对象是网页，不能据此声称 Patty 已获得某个百分比的效率提升。[Baughan 等：Keep it Simple](https://naomi-yamashita.net/wp-content/uploads/2020/05/2020jp-02.pdf)

### 把低频信息放到容易找到的第二层

渐进披露把常用操作放在首层，把低频选项留给用户主动展开；二级入口必须表达清楚内容，避免多层嵌套。Patty 已有菜单、命令面板和会话预览，可以用这些入口承接细节，而非新建永久面板。[NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

Apple 设计团队建议按用户目标审视功能，判断哪些需要常驻、哪些可以稍后访问。针对拥挤的列表，他们明确建议重新判断图标与副文本的必要性。对 Patty 的启示是逐字段说明“为什么现在需要看见”，而不是默认每条会话都显示相同数量的信息。[Apple：Design Evangelism Q&A](https://developer.apple.com/news/?id=s8sl4tpa)

### 高密度工具可以通过降低辅助元素的视觉重量变得安静

Linear 在 2026-03-12 的界面改版中，让侧栏退后，减少图标及其彩色底板，减轻边框和分隔线。其目标是在保留信息密度时减少拥挤感。Patty 可以借鉴这种层级处理，继续保持紧凑布局，同时弱化无须操作的辅助元素。[Linear：A calmer interface for a product in motion](https://linear.app/now/behind-the-latest-design-refresh)

### 终端产品已经在区分“正在运行”和“需要用户处理”

Otty 的任务监控文档说明，持续显示运行徽标默认关闭，原因是会造成噪声；等待输入和完成状态另有提示。其 1.6.1 更新还把 Inbox 和悬停预览作为有意打开的上下文入口。借鉴重点是提示的时机和分级，不需要复制整套 Inbox、编辑器和详情面板。[Otty：Monitor Tasks](https://docs.otty.sh/agents/parallel-tasks)、[Otty 1.6.1 更新](https://docs.otty.sh/changelog#_1-6-1)

Ghostty 提供未聚焦分屏淡化和分屏放大相关配置，帮助用户识别当前目标。Patty 第一轮只降低非活动标题和边框的重量，保持终端正文及 ANSI 颜色可读。正文淡化会影响日志对照，暂不采用。[Ghostty：unfocused-split-opacity](https://ghostty.org/docs/config/reference#unfocused-split-opacity)

### 安静的界面仍须可读、可发现、可用键盘操作

正文和必要副文本按普通文字至少 4.5:1 检查对比度。识别控件及必要状态的非文字线索按适用条件检查 3:1。减少文字和边框的数量，比无限调低透明度更可靠。[W3C：文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C：非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

悬停或焦点触发的补充内容应当可关闭、可移入，并持续到用户移开或主动关闭。详情入口还需有键盘路径。[W3C：Content on Hover or Focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)

以上资料提供原则和参考案例。下文的具体字段、尺寸、排序与验收目标是针对 Patty 的设计建议，尚待原型和任务测试验证。

## 当前界面的具体问题

### 可定位的证据

| 区域 | 当前实现 | 为什么增加注意力负担 |
|---|---|---|
| 侧栏顶部 | 标题与数量、新建、搜索、完整筛选下拉框、下一待处理按钮 | 即使没有待处理任务，筛选和不可用的跳转入口仍占一整行 |
| 会话行 | 图标、名称、状态图标及文字、未读点、目录或远端、工具名称 | 一条记录同时承担识别、监控、环境说明，较窄时名称被挤压 |
| 普通运行 | 后台工作中的 Agent 还会渲染 ContributionGrid 活动效果 | 持续活动并不必然要求用户转移注意力 |
| 待处理事件 | 状态颜色、状态图标、短标签、未读点、一次性光效共同出现 | 同一事件被多种方式重复强调，完成与阻塞也都带有彩色表现 |
| 分屏 | 每个 pane 都有边框、圆角、标题条、标题、目录、分隔线和操作 | 分屏越多，应用装饰和重复说明越多 |
| 分屏操作 | 当前 pane 的操作因 focused / focus-within 持续显示 | 用户在终端输入时仍会看到整组分屏和关闭按钮 |
| 底部状态栏 | 再次显示会话名、Shell、路径或远端、PID，以及 Metrics / Monitor 入口 | 与侧栏、标题重复，诊断字段持续占据界面 |
| 设置 | 标题栏和侧栏底部都有入口 | 同一操作占用两处常驻位置 |
| 会话预览 | 鼠标进入或键盘焦点停留 400ms 后显示多字段卡片 | 解决了截断，但逐行导航时仍会弹出较大的信息块 |
| SSH 会话 | 除终端本身外，底部始终显示额外命令输入栏 | 输入位置增多，也持续占据终端空间；需单独验证使用价值 |
| 命令面板 | 空查询显示完整匹配集合，每项都有图标、说明和快捷键 | 主动打开时可接受，但默认内容仍可以更聚焦；优先级低于工作界面 |

## 目标与边界

用户持续工作时，需要直接回答这些问题：当前输入送到哪里、怎样找到另一条会话、是否有任务需要自己处理。

第一轮验收应包含：

- 能区分当前输入 pane、侧栏选中会话和键盘焦点。
- 通过名称找到会话；存在同名或同目录末段时，保留足够的区别信息。
- 等待批准、等待回答和错误保持可发现；普通运行不持续吸引视线。
- 远程会话的目标可识别，不能依赖记忆猜测当前是否连到远端。
- 完整路径、工具、PID、监控入口仍可通过明确入口找到。
- 搜索、筛选、分屏、关闭、详情都能用键盘访问，关闭临时界面后焦点回到合理位置。

本轮不涉及新的后端状态协议、AI Resume、系统通知、布局模板、全新配色、字体替换、永久详情侧栏、全局重新排序或新的导航体系。也不将 CLI / TUI 自己输出的内容作为本轮删减对象。

## 设计方案

### 建立信息的固定归属

| 信息 | 默认归属 | 其他位置的规则 |
|---|---|---|
| 会话名称 | 侧栏，用于寻找 | 分屏标题保留，用于确认局部输入对象；底部不再重复 |
| 当前 pane | 分屏标题与单一焦点标识 | 侧栏的选中背景保持克制，不能与 pane 焦点混用 |
| 本地目录 | 用于区分会话时显示简短上下文 | 完整路径进入会话详情；在标题栏与行副文本之间择必要位置展示 |
| 远程目标 | 远程会话行与 pane 标题 | 保留有意义的身份重复，完整用户、端口与目录在详情中查看 |
| 工具类型 | 图标用于快速识别 | 需要区分或查看详情时显示文字，不重复堆叠品牌图标和工具标签 |
| 是否需要处理 | 行内状态；顶部只做聚合导航 | 聚合数用于跳转，不再额外播放整行光效 |
| 未读 | 单一、静态、低强度标识 | 不与工作中或错误状态合并成一个不明含义的点 |
| PID、Shell 详情 | 会话信息 | 默认工作界面不常驻 |
| Metrics / SSH Monitor | 明确的菜单及命令面板命令 | 按需打开；被收起后不能丢失入口 |
| 设置 | 侧栏底部保留一个常驻入口 | 命令面板与快捷键继续保留；标题栏移除重复图标 |

“一个信息一个归属”允许必要的局部冗余。例如用户输入时需要确认 pane 的远程目标，这比单纯追求去重更重要。

### 侧栏默认少展示一层，筛选按需展开

建议顶部维持两行：会话标题加现有新建入口；一条简短的“查找会话”入口加筛选按钮。搜索保持可见，不把核心能力全部藏进图标。

默认不显示 `All (N)` 的完整下拉框，也不显示不可用的“下一待处理”按钮。筛选内容移入有名称的菜单。选中非默认筛选后，必须持续显示筛选名称及清除操作。

存在待处理项时，在稳定位置出现“待处理 N”和下一项操作。点击待处理进入现有筛选能力，下一项沿用当前跨工作区定位流程。数量归零后，如果用户正在该筛选中，保留“待处理 0”的空状态和退出入口，避免界面自行换视图。

会话顺序继续由用户组织，后台状态变化不能自动将行移到另一处。不根据会话数量偷偷切换单行或双行布局。

普通本地会话优先展示名称。只有目录、工具或其他上下文确实能帮助区分时显示一行副文本。远程会话保留简短目标。同名会话通过最短足够区分的路径或连接信息消歧，完整值可查看。

集合是用户组织结构，不能仅凭集合名称推断所有会话位于同一项目目录。只有真实目录数据支持时，才能省略重复目录。

### 状态提示按是否需要行动分级

| 真实状态 | 建议默认显示 | 展开后 | 行为约束 |
|---|---|---|---|
| 普通 Shell / idle | 无状态徽标 | 工具与真实状态 | 安静不等于宣称任务成功 |
| working | 必要时保留小型静态运行图标 | 显示“运行中” | 去除活动网格、整行流光及持续旋转 |
| complete，未读 | 低强度的静态完成标识 | 显示“已完成，未读” | 不与批准或错误使用同等强度的彩色标签 |
| complete，已读 | 不再额外强调 | 仍能查到真实状态 | 不修改底层状态 |
| waiting_approval | 琥珀色图标和“待批准”短文本 | 原始状态信息 | 查看或选中后仍显示，直到真实状态改变 |
| waiting_input | 琥珀色图标和“待回答”短文本 | 原始状态信息 | 与待批准用文字区分 |
| error | 红色图标和“错误”短文本 | 原始状态信息 | 不因已读或选择而假装恢复 |
| unknown | 小型静态未知标识 | 显示“状态不可用” | 不用绿色或空闲图标暗示正常 |

等待、错误属于运行状态，未读属于通知信息。设计不得把“查看过”解释成“处理完”。同一行可以表达这两个维度，但不再同时堆叠完整徽标、额外亮点和光效；具体合并方式通过静态标识和无障碍名称验证。

这里不修改现有状态协议。若实施时发现当前筛选计数与持续可见的状态存在冲突，应先明确产品语义并补充测试，再调整规则。

### 分屏保持清晰的输入目标，减少框线与按钮

先保留现有 34px 标题条，避免通过缩小点击区域获取空间。标题中保留名称；目录只在辅助定位有价值时出现。远程目标持续可见，较窄时采用最短可区分表示。

当前 pane 使用一种清楚的焦点处理，移除没有额外作用的重复描边；必要焦点对比度仍需验证。其他 pane 的标题和边框降低重量，终端正文不整体降低透明度。

分屏和关闭按钮改为标题条悬停或其内部键盘操作时显现。用户在终端正文输入时，不因整个 pane 的 focus-within 而让操作按钮一直出现。为键盘保留稳定的“窗格操作”入口和现有命令面板操作。辅助技术和无悬停设备同样能访问。

按钮显隐不改变标题占位，避免会话名称与远程目标左右跳动。第一轮不默认隐藏单 pane 标题条，侧栏收起时仍然有输入目标；也不淡化用于对照阅读的另一个终端正文。

### 底部退出诊断职责，详情改为主动查看

把会话名、Shell、完整目录和 PID 从常驻状态栏中移出。先补齐“会话信息”“性能监控”“SSH 监控”的菜单及命令面板入口，然后收起重复状态栏。没有未迁移的信息和入口后，正常工作态可以不显示底栏。

会话信息使用轻量、临时的详情界面，复用现有展示数据。只有用户请求时才展开完整路径、工具、状态、远程连接和 PID。第一轮不加入 Git、文件树、日志摘要等新信息。

不让键盘逐行浏览都自动弹出大卡片。详情提供明确的键盘入口；悬停预览只在截断或存在歧义时辅助出现。可先试验 600ms 的悬停等待，但它是待验证参数；当前实现为 400ms。快速经过、拖拽、重命名和弹窗期间不展开。

现有 tooltip 中不直接塞入复制等交互按钮。若详情需要交互，使用具备正确焦点管理的独立临时界面。Esc 关闭，关闭后回到原触发位置，不改变当前终端选择。

### SSH 命令栏单独验证，避免未经验证就删功能

当前 SSH 页面会同时提供终端输入和额外命令输入栏。先记录用户是否依赖后者的历史与补全，再比较常驻和按需展开两种方式。

推荐方向是默认收起，提供可见的“命令输入”菜单项和命令面板入口；打开时明确显示目标，保留未发送草稿，Esc 返回终端。这属于第二阶段行为调整，应独立交付。不能在第一轮清理底栏时顺手删掉。

### 命令面板只在用户调用后提供更多能力

命令面板已经是临时界面，不是正常工作态的主要噪声来源，放在后面处理。

空查询优先显示少量高频操作，初始试验可用 6 至 8 项；提供清楚的“全部命令”入口，搜索仍覆盖完整命令集合。主题和 SSH 配置在用户搜索或进入相关类别时出现。第一轮不新建推荐算法或持久化最近使用系统。

删除重复的装饰箭头和无意义的“应用级”说明。关闭会话与关闭 pane 的范围、SSH 目标、禁用原因仍须在执行前可见。选中项可以承接补充说明，不能用精简文案掩盖操作范围。

### 视觉规则统一跟随信息层级

- 沿用系统字体和现有 Graphite 主题，主信息优先使用现有 13px 规格，避免继续缩小。
- 副文本减少数量，保留的文本仍需满足对比度要求。先试验 12px 的必要副文本，结合 160px 侧栏和显示缩放验证。
- 中性色承载普通图标、分组与非活动区域。主题强调色表示当前选择和主要动作；琥珀、红色表示等待和错误。
- 普通本地会话不再因自动分配颜色而呈现一串不同彩色图标。用户已有自定义颜色仍可在详情和设置中保留，不悄悄改存储值。
- Agent 的图形身份可以保留，优先去掉彩色底板和大面积发光，不必把不同工具强行变成无法区分的统一符号。
- 用对齐与间距表达分组，删除多余竖线与嵌套边框。控件和焦点所必需的边界保留。
- 默认状态没有装饰性循环动画。普通异步反馈不能反复播放提醒；临时界面开关使用短过渡并遵守减少动态效果偏好。
- 深色和浅色分别验收，不把深色方案简单提高透明度当成浅色方案。

## 路线比较

| 路线 | 收益 | 代价 | 判断 |
|---|---|---|---|
| 只改颜色、字号、间距 | 风险较低，改善局部观感 | 重复信息和常驻控件仍在 | 可作为收尾，不能独立解决本问题 |
| 信息去重、提示分级、细节按需出现 | 正常工作更安静，同时保留多会话导航 | 需要补齐入口、焦点和状态回归验证 | 推荐作为默认界面 |
| 默认隐藏全部侧栏和标题 | 终端可用面积最大 | 多会话寻找、远程目标和待处理发现变差 | 已有侧栏开关可供主动使用，不作为默认 |

暂不增加“极简 / 标准 / 专业”多套复杂模式。先做一个合理默认，验证后再判断是否确实需要更多个性化设置。

## 按优先级交付的 4+1 计划

### 目标

降低默认工作界面的信息竞争，保持会话识别、待处理发现和键盘效率。以信息归属和状态语义为先，再微调颜色和间距。

### 非目标

不新增后端能力、导航体系、系统提醒或永久面板；不修改 Shell/TUI 输出；不恢复已暂停的 AI 恢复功能。

### 影响模块

第一阶段涉及 Sidebar、SessionItem、SessionPreview、TitleBar、PaneView、StatusBar、applicationCommands / usePaletteCommands 和相关组件测试、浏览器验收场景。后续阶段才涉及 SSH CommandBar 和命令面板的默认内容。

详情入口和监控入口的迁移必须先于旧展示删除完成，不能留下“界面更干净但功能找不到”的中间交付。第一阶段复用当前状态数据；持久化或后端协议变更不属于当前计划。

### 回滚策略

每个提交对应一种可独立验收的行为变化。按依赖逆序回滚；入口迁移和旧入口删除应放在同一提交，保持功能可达。避免增加一次性的兼容层或将旧、新两套界面长期并列。

### 提交拆分

| 顺序 | 建议提交 | 交付范围 | 完成标准 |
|---|---|---|---|
| 准备 | 固定对比场景 | 复用现有浏览器验收页面，补普通运行、多个等待、长路径和 SSH 场景 | 保存当前截图与操作基线；不改变产品行为 |
| 1，最高 | `refactor: unify session detail and monitoring entry points` | 补会话详情、Metrics、SSH Monitor 的菜单和命令入口；移出 PID 与重复底栏；去掉顶部重复设置 | 所有原能力可达，关闭详情恢复焦点，远端目标持续可识别 |
| 2，最高 | `feat: simplify sidebar information hierarchy` | 按任务精简会话副文本，筛选按需展开，待处理入口按状态出现 | 普通态顶部减少一行；筛选状态可见；同名会话可区分 |
| 3，高 | `feat: prioritize actionable session states` | 去除活动网格与光效，普通完成弱提示，等待与错误保留短文本 | 切换、已读、状态恢复、未知状态都有行为测试；无装饰循环动画 |
| 4，高 | `refactor: reduce pane and toolbar visual noise` | 精简 pane 上下文、重复边线和按钮常驻，统一必要图标与颜色 | 输入目标明确，远端身份不丢失，键盘可访问窗格操作 |
| 5，中 | `feat: reveal ssh command input on demand` | 仅在使用验证支持后实施，补入口、展开、草稿与返回焦点 | 历史、补全、中文输入及目标会话正确；收起不丢草稿 |
| 6，中 | `refactor: focus command palette defaults` | 精简空查询、重复图标与泛化描述 | 全量命令仍可找到，危险操作范围始终明确，既有导航闭环通过 |

原型先比较“有条件副文本”和“统一简短双行”两种会话行，用真实长度与相同任务选定。方案推荐有条件副文本，但实施前应先验证同名识别，不能仅凭截图决定。

实施顺序按可达性和依赖安排，非按视觉变化大小安排。第一阶段先完成提交 1 至 4，再评估 SSH 输入与面板精简，避免多项行为同时改变后无法判断效果。

## 如何证明改善

### 固定场景

使用 4、12、30 个会话；分别覆盖浅色、深色；160、264、320px 侧栏；单 pane、双 pane、四 pane；Windows 100%、150%、200% 显示缩放。

至少包含：同名会话、不同项目但目录末段相同、同主机不同用户或端口、长 SSH 目标、多个等待和错误、未知状态、完成未读、已读但仍待批准、全部无待处理、筛选中数量归零。

### 行为门槛

1. 用户能从名称找到目标并正确聚焦 pane；键盘流程不能向终端误发字符。
2. 正常工作态没有循环活动装饰，没有重复 PID、Shell 与完整路径底栏。
3. 所有已支持操作仍可通过清楚入口访问；通过原有主入口完成的高频操作不增加步骤。
4. 等待与错误在未读清除后保持正确表达，直到真实状态改变。
5. 切换会话不会自动重排行、清空用户筛选或弹出抢焦点界面。
6. 远程目标与同名差异不因精简而消失；关闭命令仍明确区分 pane 和会话。
7. 必要文字、控件和焦点通过适用对比度检查，临时详情支持关闭、键盘与减少动态效果。

### 小规模用户对比

建议先找 5 至 8 位符合产品用户画像的开发者，交替体验当前版和原型，顺序交错，使用等价任务减少熟悉效应。这是早期方向验证，不作为统计显著性实验。

| 任务 | 记录 |
|---|---|
| 12 条会话中找到指定本地会话 | 完成时间、点错次数、是否依赖截断信息 |
| 识别两个同名但不同远端的会话 | 目标判断、误选次数 |
| 工作时发现新增的待批准或错误 | 是否发现、发现时间、是否误以为已处理 |
| 查看完整路径和 PID | 是否找到入口、操作次数 |
| 分屏并返回输入 | 完成时间、焦点错误、操作菜单可发现性 |
| 收起并重新打开 SSH 命令栏 | 是否找到、草稿是否保留、目标是否明确 |

分别询问视觉干扰程度和对远程目标判断的信心。不能只问“哪个更高级”。建议目标为常用寻找任务不变慢、误操作不增加、干扰评价改善；有退步就调整信息分配，不用审美偏好覆盖任务失败。

### 工程验证与现有限制

复用当前组件行为测试和浏览器验收工具，不另建一套框架。测试焦点、菜单可达、筛选持久展示、状态与未读独立、详情显隐、长文本和动态更新。截图对比相同内容与尺寸。

当前原生 WebView2 的桌面自动化调试连接仍有环境阻塞。浏览器组件验收不能替代 Windows 原生缩放、窗口拖拽与真实远端会话验收；这些需要在最终桌面构建中单独检查，不将历史通过的构建或本轮研究视为新方案已验证。

## 本轮产出与下一步

本轮完成证据整理、界面问题定位、字段归属、状态分级、分阶段计划与验收标准。尚未修改或验证提案中的产品行为。

建议下一次实施先固定对比场景，并具体审阅会话详情与监控入口的迁移。第一轮以提交 1 至 4 为范围，完成后再决定是否调整 SSH 输入栏和命令面板。布局模板和其他新功能继续暂停，防止在信息层级稳定前继续扩大常驻界面。
